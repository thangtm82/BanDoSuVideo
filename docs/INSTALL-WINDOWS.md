# BanDoSu Studio Desktop — Windows installation

## Supported environment
- Windows 10 or 11 x64
- .NET 10 SDK; Visual Studio with WPF/Desktop workload
- H2 Studio engine already tested at `D:\BanDoSu\h2-2d-studio`
- Node.js, Python 3, FFmpeg, Playwright Chromium, numpy/scipy/soundfile for the existing Studio

## Build

```powershell
git clone https://github.com/thangtm82/BanDoSuVideo.git
cd BanDoSuVideo
dotnet restore BanDoSu.slnx
dotnet build BanDoSu.slnx -c Debug
dotnet run --project src/BanDoSu.Desktop/BanDoSu.Desktop.csproj
```

On first launch, open **Cài đặt** and configure three folders:

| Field | Example | Purpose |
| --- | --- | --- |
| H2 Engine | `D:\\BanDoSu\\h2-2d-studio` | Existing `render.mjs`, Node, Python and map packs |
| Workspace | `D:\\BanDoSu\\Projects` | New projects, including scripts, shots and intermediate builds |
| Exports | `D:\\BanDoSu\\Exports` | Copies of final files from a project's `out` folder |

These roots must be independent, with neither Workspace nor Exports inside the engine. **Existing projects remain in `<engine>/projects` and are listed alongside new Workspace projects; no automatic migration is performed for old projects.** No need to copy the engine into this repository. Save settings and run Studio doctor.

## Workflow

1. **Projects**: create or select a project.
2. **Script & Voice**: paste narration, use `|` to delimit segments, save, select folder of `1.mp3`, `2.mp3`, etc.
3. Select **Validate MP3 count**, **Prepare voice timeline**, then **Generate draft shots**.
4. **Map Scenes**: select scene and edit JSON `args`; apply and save. The source engine's templates interpret these arguments.
5. **Live Map**: start WebView2, select a scene (fills the timeline slider), then seek. Press Refresh scene data after saving changes.
6. **Render & Preview**: run Check, Contact sheet and Preview; after inspection choose Full render, Mix audio, Thumbnail.

Output remains inside `<studio>\projects\<name>\out\`.

## Important limitations

- Narration MP3 creation remains external: this app imports numbered MP3 files, it does not generate voice with AI.
- This is a first functional editor implementation, not a replacement for the engine or a fully featured drag-and-drop multitrack NLE. Scene timings are generated by `draft_shots.py`; scene `args` are edited with JSON.
- WebView2 displays the actual H2 Canvas map. Playback is frame seeking, not yet synchronized real-time audio/video playback.
- H2's sample project may omit `timeline/words.json` and `timeline/lines.json`. These cause harmless 404s in the original player; the source engine may be patched separately to skip optional timeline fetches when captions are disabled.
- Always keep a backup of the project before rerunning `draft_shots.py`.
- Build and rendering require Windows, the existing Studio installation and its dependencies. This workspace could not compile WPF because it does not have a .NET SDK; verify on Windows or a Windows CI runner.

## Smoke test

Open `bando-mau` in Projects, click Contact sheet and Preview first 30s. Verify the map and preview. Then create `test-hoa-lu`, import existing voice TXT and MP3s, generate draft scenes, edit their args, save, run Check, Preview, Full render, Mix audio, Thumbnail.

## Packaging

```powershell
dotnet publish src/BanDoSu.Desktop/BanDoSu.Desktop.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=false
```

The H2 engine remains external, because its map assets and runtime dependencies are large. This deliberately avoids bundling or relicensing third-party assets.

## Path compatibility and operational notes

The upstream H2 scripts generate new projects under `<engine>/projects`. BanDoSu Desktop runs that generator and **moves only the newly created project** into Workspace when generation succeeds. An existing engine project is never moved or deleted by that workflow. A project name already used by either Workspace or the legacy engine location is rejected during creation.

Existing projects are detected automatically and continue using their original path. For new Workspace projects, the CLI receives an **absolute project path** in `--project`, and the preview server receives `--project-dir`. Whether an individual version of the upstream H2 renderer handles absolute project paths correctly must still be tested with your installed engine before relying on production exports.

If engine and workspace are on different drives, the initial project move copies the project to the workspace and removes its temporary engine source only after verification. Keep backups of important projects; projects are not automatically migrated between configured workspaces.

A successful Windows CI build checks the .NET app and core path logic but does not execute the external H2 engine end-to-end.
